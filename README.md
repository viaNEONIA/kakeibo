## 移行手順
1. GitHubで空リポジトリを作成し、資料をmainへ登録。
2. Workにリポジトリと`docs/WORK_HANDOVER.md`を渡す。
3. Workは最初に仕様レビューとIssue化のみ実施し、承認前にアプリを実装しない。
4. 未確定事項を解消し、実装ブランチで開発・試験。合格後にmainへ統合。

## 親バックアップからの復旧（0.4.4-dev）

設定の通常JSON復元で、初期状態の端末に親バックアップを選ぶと「親として復旧」の確認を表示します。家計簿ID/親端末ID/子登録/履歴を保持し、既存の子を登録し直す必要はありません。旧親は同時使用しないでください。[復旧条件・手順・試験](docs/PARENT_RECOVERY.md)を参照。

## JSONファイルの保存（0.4.5-dev）

通常バックアップ・統合用ファイル・子参加ファイルは、作成後に保存リンクを表示します。自動ダウンロードが始まらない場合は「JSONを保存」を直接押してください。対応環境では「ファイルを共有」も使えます。ファイルは作成時点の内容です。入力を変更した場合は作り直してください。保存完了はダウンロード通知・保存先で確認してください。サイトデータの削除は不要です。

[修正内容と試験結果](docs/FILE_SAVE.md)

## JSONファイルの見分け方（0.4.6-dev）

保存名の先頭は `kakeibo-復元用バックアップ-` / `kakeibo-家族統合用-` / `kakeibo-子参加用-` です。続けて親・子・単独の区分、共有端末名・端末IDの先頭8文字（共有時）、作成日時（UTCのZ表記）が入ります。ファイル名を変更しても読込可否の判定には影響しません。

読込確認画面で用途・作成元端末・作成日時（日本時間）・家計簿ID・実行する操作を確認してください。復元は保存時点への全量上書き、統合は変更の反映、子参加は新しい子端末の登録です。通常バックアップを統合に使う既存の対応も維持し、ファイルの用途と今回の操作を別々に表示します。単独利用の旧バックアップには端末名の記録がないため、不明な情報を補いません。

## JSONの共有（0.4.7-dev）

保存画面に「保存したJSONを共有する手順」を常時表示します。「JSONを保存」後、ファイルアプリやダウンロード一覧から表示された名前のJSONを選び、共有してください。すでに保存済みなら再保存は不要です。

対応を申告する環境では「アプリから共有（対応環境）」も表示しますが、共有先・ブラウザーの制限で失敗する場合があります。失敗時はエラー種別と保存先から共有する手順を表示します。権限やファイル種類の制限はアプリだけでは解除できません。拡張子・MIME型の偽装や別形式への自動変換は行いません。

## 繰越プール目標（0.5.0-dev）

予算画面で適用開始期間と目標額を設定できます。変更・解除履歴、達成率・不足額、期間別の当時目標、初回達成の記録を表示します。共有中は親が管理し、子は統合用JSONで更新します。達成予定月の推定は含みません。[操作・計算・通知方式・試験結果](docs/GOALS.md)を参照。
