# CALCULATION_SPEC — 計算単体仕様 v1

根拠: 承認済みSPEC・OPERATIONS_DECISION・CARRYOVER_DECISION。金額は整数円。UI・DBへ直接アクセスしない計算処理の入出力契約を定義する。実装は未作成。

## 期間と日付

入力はCivilDateと不変periods配列。日付がstartDate<=date<=endDateを満たす期間を1件返す。0件は期間生成/欠落エラー、2件以上は整合性エラー。日付を端末ローカル時刻のUTC変換でずらさない。
通常期間は開始日1〜28日、翌月同開始日の前日まで。初期開始日1は暦月末終了。labelMonth=endDateの年月。変更は現期間を締めた翌日から、新しい通常開始日の直前までを移行期間として接続。端数が0日なら移行期間を作らない。
定期予定日は暦月のmin(指定日,その月の日数)。予定の一意性は暦月キー、実績の集計所属は発生日から判定する。

## 収支と予算

期間pの入力取引からI=income合計、G=expense合計、F=refund合計、E=G-F（純支出）を算出。収支=I-E。返金は返金日で計上し元支出日の金額を変更しない。Eは返金により負になり得る。
基本予算B、プール配分A（有効な配分の総額）、利用可能V=B+A、残予算R=V-E、未振分U=V-項目予算合計。
新規の振分保存はU>=0が条件。支出登録は予算超過を理由に拒否しない。過去の予算/配分修正で既存振分が超過した場合は不整合を示し、過去の実績や配分を削除して帳尻を合わせない。修復UIの追加判断は必要時にIssue化。
使用率はV>0でE/V*100。表示の丸め値ではなく元の比で警告判定。初期閾値80%、100%は使い切り、100%超は超過。V=0は除算しない。負の純支出を0へ切り捨てて集計しない。

## 精算・台帳

期間精算目標S=B+A-E。P=前期末実残高、J=当期調整、N=P-A+S+J。確定後N=P+B-E+Jとなり、Aの移動を二重消費しない。
新規確定: 反映差額D=S。再確定: D=S-旧反映精算額。Dが0なら台帳増減を追加せず、操作の成功結果を保持する。台帳deltaはopening:+初期額、allocate:-配分額、adjust:符号付き、settle:D、reverse:対象の反対符号。
同一台帳をreverseできるのは一度だけ。配分取消は元配分との対応でAを減らし、プールへ戻す。再精算は変更後Aで差額計算し、取消と未使用戻しを重ねない。

見込みSは保存された精算と分離。未締め期間の見込みを、確定台帳へ勝手に反映しない。台帳からの実残高と、未締め期間を精算した場合の見込み残高を混同しない。
過去取引・予算・配分変更は影響する最古期間から順に再計算。既に締めた期間は最新入力に対応するDを付けた監査履歴を原子的に反映し、後続残高を更新。初回締めは必ず手動。自動再評価の履歴理由を明示する。この扱いは承認済みの「過去修正後の再計算」と「再確定差額反映」の保存設計であり、新規の自動締めではない。

## 不足と目標

配分可能=max(実残高,0)、未精算=max(-実残高,0)。後月の正の精算を台帳へ一度反映すると不足が減る。未精算額を別途控除しない。
新規配分は保存直前の実残高を再読込し、不足中は停止、配分可能額を超える配分は保存しない。既存履歴の再計算で負になる場合は記録を保持する。
目標Tは1以上、未設定時は割合非表示。達成率=N/T*100、不足額=max(0,T-N)。100%超を許容し負残高も隠さない。達成通知は有効な目標設定IDごとに一度。目標変更で新IDとなり、解除で割合表示を止める。過去推移は当該期間で有効な履歴を用いる。

## 固定受入例

| ケース | 入力 | 期待 |
| --- | --- | --- |
| 正常繰越 | P30,000 B100,000 A20,000 E110,000 J0 | S10,000 N20,000 |
| 超過 | 同上E140,000 | S-20,000 N-10,000 未精算10,000 |
| 保留解消 | N-10,000に精算+6,000、+7,000 | N-4,000→3,000 未精算4,000→0 |
| 再確定 | 反映済S10,000、同一入力 | D0、台帳残高不変 |
| 過去修正 | E110,000→125,000 | S10,000→-5,000、D-15,000、N5,000 |
| 配分取消 | 正常例からA20,000を取消、Eは110,000のまま | 配分返却+20,000、Sは-10,000、精算差額-20,000、N20,000不変 |
| 返金 | E110,000の期間でrefund5,000 | E105,000、S15,000、N25,000 |
| 収入非連動 | Iを50,000増加、その他不変 | 収支のみ+50,000、予算/精算は不変 |
| 目標 | N-10,000 T50,000 | 達成率-20%、不足60,000 |
| 振分 | V100,000、合計100,001 | 振分保存不可、実績支出は登録可能 |

期間例: 2026/10/25〜11/24は11月分。2026/10/1〜10/31→11/1〜11/24移行→11/25〜12/24で連続。逆方向11/24終了→11/25〜11/30移行→12/1開始も連続。2028/2の31日指定は2/29。2027/2は2/28。端数期間の予算は手動であり自動日割りしない。

検証例は設計レビュー用。アプリ計算関数やDBの動作試験合格を意味しない。
