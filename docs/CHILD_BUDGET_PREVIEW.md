# 子の予算仮表示 — 0.4.2-dev

## 表示

家族共有の子端末だけに、選択中の集計期間の仮集計カードを表示する。

- 収入、支出（返金差引）、返金、残予算を表示。親確認済み金額と残予算の差も表示する。
- 項目別振分の下に親確認済み支出と仮支出を表示。基本予算と項目別振分は親が設定した値を使い、子では読み取り専用。
- 収入は予算へ自動加算しない。残予算は「基本予算＋プール配分−純支出」。予算0・返金・負の残予算も既存の計算規則に従う。
- この期間の確認待ち取引件数を表示。他期間だけに確認待ちがある場合は、その旨を分けて示す。
- 親から全変更の確認結果を取得した期間は「親の統合結果を反映済み」と表示し、仮ラベルを外す。

この端末が保持する取引の仮集計であり、未受信の別端末の取引や最新予算を推定しない。競合で採用される内容が変われば、親結果取込時に金額も変わる。

## 親との往復

1. 子で入力/編集/削除すると、保存直後に仮集計へ反映。再起動後も同じ状態を導出できる。
2. 子のJSONを親が統合しても、子には通信がないので仮表示を維持。
3. 親の統合後JSONを子へ取り込むと、親のスナップショットと確認済み変更IDで表示を更新する。
4. 親のファイル作成後に子で追加編集した変更は、親確認済みへ誤昇格せず仮として残す。
5. 競合で不採用になった変更も親の確認対象に含まれる。仮表示が解除されても不採用内容を復活させない。

確定プール残高・配分可能額・未精算額・期間別推移は親の確定結果を表示する。仮集計のために台帳へ精算を追加しない。締め済み期間の取引も、子では仮集計のみ更新し、親の統合確認時に差額精算、その結果を子へ配布する。

## 保存と互換性

交換ファイルの任意parentEventIdsは親が確認した変更ID群。子のmeta.state.sharing.confirmedEventIdsへ保存し、転送でも元の確認範囲を維持する。どちらも既存events内の一意なIDを検証する。親・未共有端末には仮集計カードを出さない。
DB版2/共有バックアップ形式2/交換形式1を維持する。旧状態で確認情報が欠落していれば、確認済みと推測せず不明の仮表示とする。旧親ファイルを親本人から取り込む場合は、そのevents全体を親の確認範囲として使用できる。旧子ファイル経由で新しい親版を受け、確認範囲が分からなければ不明を維持する。古い親版で最新の確認情報を巻き戻さない。

## 配信後の確認手順

1. 親と子を0.4.2-devへ更新する。
2. 親の予算と直近の共有結果を子へ取り込む。
3. 子で収支を登録し、予算画面の仮集計・確認待ち・項目別支出を確認する。
4. 子のJSONを親へ取り込み、親が出力した統合結果を子へ取り込む。
5. 確認待ちの解除と金額更新を確認する。取込前に追加入力した取引は仮として残ることも確認する。
