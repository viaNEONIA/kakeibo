# 家族共有 — 0.4.0-dev / Issue #20

## 承認事項

家族で同じ家計簿を複数端末から共有する。最初の端末を親、追加端末を子として登録。当面はJSONの手動交換で統合し、クラウド交換は将来項目。独立家計簿同士の合算は対象外。
真の並行編集・編集対削除では親を優先し、子同士は親が登録した順序の早い端末を優先する。親の未編集の古いコピーで子の後続編集を潰さない。競合の採用/不採用内容・理由を表示。月締め・再締め・精算確定は親専用。締め後に届いた子の取引は親で影響確認後に差額精算する。

## 操作手順

1. 全端末を最新版に更新する。既存データのある親で通常のJSONバックアップを保存し、「設定 → 家族で共有」で親端末の名前を設定する。
2. 親で子の名前を登録すると、その子専用の参加ファイルが保存される。子1台につき別々に登録する。同じ参加ファイルを複数台に配らない。
3. 子で「子として初回参加」からそのファイルを選び、全量置換の説明を確認して参加する。子に既存データがあれば先に通常バックアップを保存する。独立した既存データの自動合算はしない。
4. 子は収入・支出・返金を入力/編集/削除し、「統合用JSONを保存」で親へ渡す。親は「統合用JSONを取り込む」で件数・競合・確定プール残高への影響を確認して反映する。
5. 親の統合用JSONを各子へ取り込むと、親の最新予算・項目・プール・締め結果と家族の取引が伝わる。子の未取込変更も履歴の和集合として保持する。
6. 締め前に各子の最新ファイルを集める。ファイル交換だけでは未送信取引の不存在を保証できない。締め後の取引も取込可能で、親の確認時に差額精算する。

共有設定後の通常JSONバックアップも、統合用の取込欄から取り込める。この場合も全量置換せず差分統合する。未共有時代の通常バックアップは統合対象外。

子同士でも登録済みの同一家計簿のファイルを交換できる。親が確定した予算/プール/締め結果だけを受け取り、子同士では精算しない。

## 今回の権限範囲

| 操作 | 親 | 子 |
| --- | --- | --- |
| 通常の収入/支出/返金の入力・編集・削除 | 可 | 可 |
| 項目・予算・プール・期間設定・子の登録 | 可 | 不可 |
| 月締め・再締め・精算確定 | 可 | 不可 |
| 一覧の表示設定 | 可 | 可（端末内に保持） |
| 定期リンク取引の変更 | 既存機能の範囲 | 不可 |
| ファイル出力・同一家計簿の統合 | 可 | 可 |

月締め以外の管理操作を親に集約するのは、今回の安全な実装範囲であり、追加承認済み仕様とは区別する。子の取引修正により締め済み期間の入力と精算が異なる場合、親の再精算待ちを表示する。子のプール表示は親による確定残高であり、未精算取引を加算した見込み残高ではない。

## 保存・識別・統合方式

- IndexedDB版2。版1の17ストア・キー・索引・全レコードを維持し、schemaInfoだけを移行する。版変更により旧アプリの接続を閉じ、共有履歴を記録しない旧コードでの保存を防ぐ。
- meta.state.sharingに家計簿共通ID、親ID、この端末ID、親が発行する連続登録順、親確定版、収支変更履歴を保存。datasetIdは従来どおりローカルの復元世代であり共有IDに流用しない。
- 収支変更は不変イベントID・取引ID・編集元端末・既知の先行変更ID・変更後取引または削除記録を持つ。収支更新と同じDBトランザクション内で記録する。削除履歴は自動廃棄しない。
- 取引ごとに他の変更の祖先となっていない変更を抽出する。候補が複数なら端末の優先順位で選ぶ。新しい編集は既知の候補すべてを先行変更とするため、競合解決を見た後の通常編集は因果的な後続変更として扱える。
- 親が子の変更を転送しても編集元端末IDを保持する。取込日時/端末時計/ファイル順序/レコードrevisionだけで勝者を決めない。
- 同一イベントIDの異なる内容、欠落/循環/参照不整合、別家計簿、登録順の不一致、同じ端末IDの並行編集は拒否する。
- 両端末で生成された期間UUIDは取引日と親の期間設定へ再対応付けし、同期間を重複作成しない。
- 管理データは親の確定スナップショットを版番号で配布する。子はより新しい親版だけを適用し、一覧表示設定・端末ID・未取込の取引変更・操作再試行記録を維持する。子の台帳を親へ合算しない。
- 親の取込確認で統合後取引から締め済み期間の差額を計算し、既存台帳を削除せず精算・監査履歴を追加。同じファイルの再取込でも精算を重複しない。
- プレビューのデータ世代と更新版を反映時に再検証し、確認後の更新/復元には再確認を要求。全体を同一readwriteトランザクションで保存する。

## ファイルの区別と互換性

| ファイル | 用途 |
| --- | --- |
| 通常バックアップ（kakeibo-pwa） | 全量置換による復元。未共有は形式1、共有後は形式2。DB形式版は2 |
| 旧版バックアップ（形式1/DB版1） | 未共有の現行アプリで版2へ変換して復元可能。元ファイルは変更しない |
| 子参加ファイル（kakeibo-family / exchangeVersion1） | 登録済み子IDを指定した初回参加用。全量置換を明示 |
| 統合用ファイル（同上） | 同一家計簿の管理スナップショットと取引変更履歴を交換 |

共有中の通常復元は同一家計簿だけに限定し、この端末のIDを保持する。親バックアップを子へ通常復元しても親へ昇格しない。未共有端末が共有バックアップから親を複製する操作は拒否し、初回参加は専用ファイルを使用する。古い親へ新しい確定版を取り込もうとした場合も拒否し、誤った親の二重稼働を避ける。

## 制限と未実装

- 自動通信・クラウド・アカウント認証・暗号化/署名はない。親子権限はアプリ内の操作制御であり、JSONを書き換える相手に対する認証保証ではない。ファイルは信頼できる家族間で扱う。
- 親端末の紛失時の引継ぎ、子の解除/再登録・名前変更、端末間の自動到達確認は未実装。親の故障前に代替端末を親へ昇格させることはできない。バックアップだけで別端末へ親を再作成する回復経路も未提供。
- 同じ子参加ファイルを複数台で使うことは禁止。同じ端末IDの並行編集を検出したら自動統合を拒否し、黙って片方を破棄しない。
- 共有履歴は最大100,000変更、登録は親込み100台、UIのファイル取込は25MBまで。履歴圧縮・大規模データの性能保証は対象外。
- I07目標UI・I08定期/CSVは引き続き後続。将来の管理データ機能は親の管理スナップショット方式へ組み込む必要がある。
- 実機受入は未実施。試験結果はTEST_RESULTS_SHARINGを参照。
