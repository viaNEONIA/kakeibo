# JSON保存の再試行

通常バックアップと家族用ファイルの保存を共通処理にする。従来はDOMへ追加しないリンクを非同期処理後にクリックし、1秒後にURLを破棄していた。これが特定の実機で失敗する原因と断定はしない。

## 動作
- 作成ボタンから準備状態を表示。成功するとファイル名・DOM上の保存リンクを表示し、自動ダウンロードも試みる。
- 保存通知が出なければ「JSONを保存」を直接操作。現在のファイルURLは維持し、次のファイル作成後も旧URLを60秒保持。
- ファイル共有API対応時のみ共有ボタンを表示。準備済みFileを直接のユーザー操作で渡し、取消・失敗時も保存リンクを維持。
- DB読込・JSON準備の失敗は画面表示。処理中・別タブ更新等で作成ボタンが無効の場合はボタン付近に理由を表示。
- 保存処理を要求しただけでは保存完了と表示しない。直近の日時は「バックアップ準備」と表記。ダウンロード通知・保存先で完了を確認する。
- ファイルは準備時のスナップショット。変更後は再作成。DB版・バックアップ形式・統合の意味は変更なし。

## 検証
- Node単体・IndexedDB: 61件。
- ブラウザー基盤: 13件、家族共有: 11件、親復旧: 6件。
- 追加ブラウザー試験: 6件。自動クリックを遮断した手動保存、1秒超のURL保持、通常/統合/子参加JSON、直接操作での共有API呼出、取消/失敗後の保存、準備失敗後の再試行、オフライン再起動、320px表示。
- 追加試験: `CHROMIUM_PATH=/path/to/chromium npm run test:browser:file-save`。
- Chromium自動試験であり、Android/iOS実機の保存先アプリ・共有シートは未確認。共有APIはテスト用スタブで検証。
