# I07 繰越プールの目標 — 0.5.0-dev

## 操作
予算画面の「繰越プールの目標」で適用開始期間を選び、1円以上の整数を保存する。未準備の期間は予算画面上部の日付から用意する。設定変更は新しい履歴として追加し、解除は専用ボタンと確認操作でnullの履歴を追加する。共有中の設定・解除は親専用。子は親の家族統合用JSONの読込で反映する。

## 適用と集計
- 期間の開始日順で、その期間以前を適用開始とする最新の設定が有効。同じ適用開始期間の設定はsequenceが最後のものを使う。後から過去期間を設定しても、別の未来期間に予約済みの設定は置き換えない。
- 期間IDを参照し、終了月と実際の開始・終了日を併記する。移行期間を同じ月名の通常期間と取り違えない。期間設定変更でも既存履歴の期間IDは維持する。
- 主表示は日本時間の今日を含む期間の目標と、確定済みのプール実残高を用いる。子の仮表示・将来見込みは含まない。現在期間が未準備なら案内を出す。
- 達成率=実残高/目標×100。負値・100%超を隠さず、小数1桁まで表示。不足額=max(目標−実残高,0)。目標未設定・解除は率と不足額を非表示。未精算額と目標不足額は別の概念。
- 目標は正の安全整数。極端な負残高との差は安全整数を超え得るため、保存しない導出不足額だけBigIntで正確に計算・表示する。
- プール期間別推移表には、その期間で有効な目標と期間末確定残高に対する率・不足額を表示する。過去期間を後から編集した場合は対応する導出表示も更新される。

## 達成記録・通知
- 現在期間で有効な設定と確定実残高を比較し、残高が目標以上ならgoalNotificationsへ設定IDごとに一度だけ記録する。
- 目標設定時、残高を変える操作等のDB command内で、業務データと達成記録を同じトランザクションに保存する。途中失敗なら両方とも戻す。
- 再表示時にも未記録の達成を確認する。未来の目標が有効になる場合や旧バックアップからの復元で記録がない場合も、アプリが確認した時点で記録する。アプリを閉じている間のバックグラウンド判定ではない。
- 画面内の初回達成表示と履歴が通知方式。OS通知・プッシュ権限は使用しない。同じ目標設定で減少・再達成しても記録を増やさない。同額への再設定も新IDとなり、通知状態は独立する。
- 子は達成記録を生成せず、親が配布した記録を閲覧する。親がアプリで確認した時刻を日本時間で表示する。

## 互換性・範囲
DB版2・17ストア、通常バックアップ形式1/共有形式2・交換形式1を維持する。既存のgoalHistory/goalNotificationsを使用し、旧JSONに含まれる履歴も保持する。目標達成予定月の推定は未実装。I08定期収支・CSVも別工程。
