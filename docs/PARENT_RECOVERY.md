# 通常JSONからの親復旧 — 0.4.4-dev

> 本書の見出しの版・導入時の試験数は導入時点の記録です。現行版と実装状況は[IMPLEMENTATION_STATUS](IMPLEMENTATION_STATUS.md)、受入手順は[TEST_CHECKLIST](TEST_CHECKLIST.md)、文書一覧は[INDEX](INDEX.md)を参照。

## 修正対象

従来のdb.restoreは、共有バックアップの通常復元先にも同じ家計簿の共有情報が存在することを要求していた。そのため、ローカルデータを失って初期状態になった端末へ、正常な共有親バックアップを復元する経路がなかった。
既存の共有中の上書き制限は維持しつつ、初期状態だけに明示確認付きの親復旧を追加する。通常バックアップのファイル内容を書き換える必要はない。

## 操作手順

1. ブラウザーでアプリを最新版（現在0.6.0-dev）へ更新する。設定の表示バージョンを確認する。
2. 「バックアップと復元」の通常ファイル選択から、**親で保存した通常JSONバックアップ**を指定する。統合用JSONや子参加ファイルではない。
3. 対象なら確認画面の見出しが「バックアップから親を復旧します」になる。
4. 「このバックアップの親として復旧し、旧親は同時に使用しません」にチェックする。
5. 「親として全量復旧」を押す。親として復旧した旨の表示を確認し、取引・予算・プール・子登録を確認する。
6. 既存子の未統合データがあれば、その通常の共有ファイルを復旧後の親へ統合し、親の結果を子へ配布する。

新たな親IDを作る事前操作や、子の登録し直しは不要。バックアップ原本は保存しておく。サイトデータをもう一度削除する操作を手順には含めない。

## 復旧条件

- ファイルの形式・参照・計算・履歴を通常のvalidateBackupで検証し、保存元端末IDが親IDと一致する親バックアップだけを対象にする。
- 復旧先に取引・項目・予算・予算履歴・定期・目標・締め/精算履歴などの業務データがないこと。
- プールは初期0円の記録1件だけであること。期間を表示しただけの空の集計期間/設定・表示設定は許可する。
- 共有未設定、または、子登録0件・変更イベント0件の未使用の親設定だけであること。既存子は対象外。同一家計簿として設定済みの場合は従来の通常復元を使う。
- APIでもrecoverParent:trueを明示しなければ、従来どおり初期状態への共有復元を拒否。UIでもチェックするまで復旧ボタンは押せない。

業務データや子登録がある端末を、この例外で無言に上書きしない。復旧対象にならない場合は現在のデータとバックアップ原本を保持したまま条件を確認する。

## 復旧後の識別と整合性

- 家計簿ID・親ID・親端末ID・子登録順・取引ID・変更イベント・予算・プール台帳・締め履歴を保持。
- ローカルdatasetIdを新しい世代にし、datasetRevisionを進める。旧世代の他タブからの保存を拒否する。
- parentRecovery監査情報とrecover-parent操作履歴を追加。途中失敗は全量置換をロールバックし、元データと接続世代を維持する。
- 親のmasterVersionを推測で繰り上げない。バックアップが古く、子がそれより新しい親確定版を保持している場合、従来どおり統合を拒否する。古いバックアップから失った最新データを自動復元・調停する機能ではない。
- 家計データ・子登録の複製先を新しい親として同時運用するための機能ではない。旧親を停止していることは利用者が確認する。オフライン端末を遠隔停止する機能、署名による親の所有者認証、稼働中親の権限移譲は未提供。
