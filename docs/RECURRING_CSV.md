# I08 定期収支・CSV — 0.6.0-dev

## 定期収入・支出
設定の「定期収入・支出」を開き、種類・名称・金額・項目・毎月の日・開始月・終了月（空欄は終了なし）・有効状態を保存する。予定月は家計簿の集計期間ではなく暦月で選ぶ。「この予定を確定」の確認操作で初めて実績へ登録する。予定は収入・支出・予算・プールに含めない。収入確定で基本予算を自動増額しない。

- 周期は毎月のみ。日付29〜31日がない月は暦月末へ補正する。うるう年・世紀境界も暦に従う。
- 実績の所属期間は発生日から決める。開始日25日なら3/31の予定は3/25〜4/24の4月分に属する。移行期間の追加で同じ暦月の予定を増やさない。
- ルールIDと暦月で一意。予定から確定取引へ金額・名称・種類・日付・項目をコピーしてスナップショットを保持する。ルールを変更しても確定済みの実績は変更しない。
- 未保存の予定候補は現在のルールから導出し、月を閲覧するだけではDBを変更しない。既存バックアップに保存済みのpending予定がある場合は当時のスナップショットを保持する。これはデータ保護のための実装方針。
- 既存実績と予定の二重確定を防ぐ。業務データ・予定の参照・共有イベント・締め済み期間の差額再精算は同じトランザクションで保存し、途中失敗なら戻す。
- 無効なルール・適用範囲外の予定は新規確定できない。項目が無効な場合も新規実績の確定を拒否する。既存実績は保持する。
- 実績の金額・名称・項目・メモは収支一覧から編集可能。定期リンク取引の種類・日付は従来どおり固定。削除時はvoidedとなり自動復活しない。定期枠を再確定する専用機能は今回追加しない。必要な別取引は通常入力で登録できる。
- ホームは今月・翌月の未確定候補を最大8件表示する。それ以外の月は設定の予定月から閲覧・手動確定する。
- 共有中の設定・編集・確定は親専用。子は親の家族統合用JSONを取り込んで予定と実績を更新する。子の仮支出を定期予定として自動確定しない。

## CSV
設定から「収支CSV」と「プール期間別CSV」を別々に保存する。出力範囲はこの端末の全収支・全保存期間。CSVは集計用で、アプリへの復元・統合にはJSONを使う。

収支：ID、日付、種類（収入/支出/返金）、項目、名称、金額、メモ、定期登録元ID（ルールID）、集計期間開始日・終了日。

プール：終了月の年月、月初残高、追加、配分、超過精算、調整、月末実残高、未精算額、当時の目標額、集計期間開始日・終了日、期間種別（移行/通常を識別する補助列）。未設定目標は空欄。未締めの見込みは出力しない。

- UTF-8 BOM・CRLFで出力。文字列は二重引用符で囲み、引用符は二重化する。文字列内の改行を保持する。
- 文字列先頭の数式開始記号（空白等の後の=、+、-、@）やタブ/改行開始はアポストロフィを付ける。金額は引用しない数値として出す。DBの元データは変更しない。
- 子の収支CSVには保持する未確認の取引も含む。プールは親の確定済み値。出力前に画面へその違いを表示する。
- JSONと同じ保存パネルを使い、CSVのファイル名・保存リンク・共有手順を表示する。自動保存が始まらない場合は「CSVを保存」を直接押す。JSON保存時には表示をJSONへ戻す。保存完了はダウンロード通知/保存先で確認する。

## 互換性と検証
DB版2・17ストア・通常JSON形式1/共有形式2・交換形式1を維持する。新しいストアやマイグレーションは追加しない。

Node78件、Chromium基盤13件・定期/CSV5件・家族共有11件・目標6件・保存7件、合計120件を通過。短い月/うるう年/世紀境界、収入の予算非連動、ルール変更後の実績維持、二重確定/削除後復活防止、停止/終了月、不正入力、既存pendingの維持、原子的ロールバック、期間変更・差額再精算、親子反映・権限、JSON往復、引用/改行/数式/BOM、CSVの別出力・手動リンク・オフライン・320/412pxを含む。
