# 受入試験計画 v1.3

## データ
- 収入・支出の登録、編集、削除、再起動後保持。
- 同額連続入力と直前取消。意図しない二重登録防止。
- 項目名変更・無効化後も過去取引の参照維持。
- フィルター（期間、収支、項目、金額帯、名称）、1行表示、表示切替。

## 予算・繰越
- 予算0円、超過、未振分、前月予算コピー。
- プールへの月末追加が一度だけ発生すること。
- 配分・取消・調整と月別推移の一致。
- 過去月取引修正後に後続月が再計算されること。
- プール不足時に警告、履歴を自動削除しないこと。
- 繰越配分が収入・支出に混入しないこと。
- 当月配分の未使用分による二重繰越が発生しないこと（CARRYOVER_DECISIONの承認済み数値例で確認）。

## 目標
- 目標未設定、設定・変更・解除、0円入力、100%超過、達成通知の重複防止。
- 目標履歴と月別グラフの整合性。

## 定期収支
- 予定は実績に計上されず、手動確定で1回だけ取引登録。
- 月末31日指定の短い月、無効化・終了月。

## PWA・バックアップ
- Android Chrome、iOS Safari（ホーム画面追加）、PCブラウザで動作。
- オフライン起動・入力、更新後データ保持。
- CSVのExcel読込、文字化け、数値、数式注入対策。
- JSON全量バックアップと復元、破損データ拒否、スキーマ互換性。

重大な計算不整合0件、データ消失0件、主要操作不能0件、必須試験合格。実機試験は未実施。

## 繰越の確定受入条件 — 2026-10-19

- CARRYOVER_DECISIONの支出90,000〜140,000の5例を検証する。
- 再確定で同一精算を二度反映しない。過去修正110,000→125,000の差額-15,000と後続負残高を検証する。
- 収入追加で予算が増えない。配分・精算を収支へ混入させない。
- 初期残高未変更時0円、入力した残高を保持。不足時は負残高・警告、新規配分停止、既存履歴保持。
- Q-HOLDの未精算額10,000→4,000→0、実残高-10,000→-4,000→3,000、配分可能額0→0→3,000を必須確認する。後月精算+6,000、+7,000で過去の超過額を二重控除しない。月別推移・再確定・再起動後にも実残高と導出額が一致すること。

## UI・運用決定の受入試験

[OPERATIONS_DECISION](OPERATIONS_DECISION.md)の受入条件を必須計画へ追加。定期収入の単回手動確定、超過振分拒否と支出超過許可、6項目/その他/設定順・テンキー/ナビ、目標履歴/0円拒否/通知再発防止、79/80/100/101%と予算0、金額範囲/返金日集計、日本時間境界、JSON全量復元の原子性と不正拒否、別CSV、予算だけのコピー、暦月末補正を対象にする。
任意集計期間の境界・期間変更・目標/CSVラベル・移行端数期間はOPERATIONS_DECISIONの確定ルールで検証する。機能試験は未実施。

## 集計期間の確定受入例

- 初期1日〜末日、開始日1/25/28を許可、29/30/31を拒否。翌開始日前日までを含め、境界日の取引がちょうど一つの期間へ所属する。
- 25日始まり: 2026/10/25〜11/24は11月分。目標有効月・CSV年月と実開始/終了日が一致。
- 2026/10/1〜10/31→11/1〜11/24移行期間→11/25〜12/24の接続で重複/空白0。
- 2026/10/25〜11/24→11/25〜11/30移行期間→12/1〜12/31の逆方向接続を確認。
- 2027/1/28〜2/27、2028/1/28〜2/27、2028/2/28〜3/27、2026/12/25〜2027/1/24の短月・閏年・年跨ぎを確認。
- 移行期間の予算は手動設定、自動日割りなし。コピーは予算のみで履歴複製なし、既存上書き確認あり。
- 過去の確定期間・目標・配分/精算履歴は設定変更で再編しない。期間を識別して同月ラベルでも上書きしない。
- 各期間の締め・再確定・過去修正・未精算解消は承認済み繰越式を維持し二重精算しない。

これらは受入試験計画。アプリ実装・実機試験は未実施。

## I03物理設計の受入・実装時試験

DATA_MODELの17ストア、キー/索引/参照、CALCULATION_SPECの固定数値、STORAGE_PROTOCOLの更新境界を設計レビュー対象とする。実装後は以下を確認:

- 同一月名の移行/通常期間が別IDで保持される。日付編集で旧/新期間が再集計される。
- 別IDの同額連続登録2件と、同一操作IDの再試行1件を区別。
- 同じ定期暦月を2タブから確定しても実績1件、確定後ルール編集で実績不変。
- 2タブ編集競合の検出、同時配分の不足拒否、復元後の旧世代書込拒否。
- 予算・配分変更/取消の精算差額、取引削除/返金/日付変更の後続再計算と監査履歴を確認。
- 保存の各段階で失敗しても部分更新なし、復元失敗時は旧データ全体維持。
- バックアップが全17ストアの一貫した状態であり、型/参照/期間/精算/版/重複の不正を拒否。
- 目標IDごとの通知1回、設定変更で新ID、過去表示維持。
